# WinVoice 设置界面(Web 前端版):配置可视化管理

**分支**:`git checkout -b feature/settings-ui`(基于 `feature/exe_build`)。**发版不在本任务范围**。

## 形态(回应"以后要更好看、更复杂")

**本地 Web UI,不用 tkinter / PySide6**:运行时新增 `python\python.exe -m winvoice.webui`,启动一个**只绑 127.0.0.1** 的 stdlib HTTP 服务(随机端口 + 随机 token,零新 pip 依赖),自动用 `msedge --app=<url>` 打开无地址栏独立窗口(无 Edge 则回退默认浏览器)。前端是纯 HTML/CSS/JS 静态文件(无构建步骤),以后可无痛迁移到 Tailwind/React/ECharts——**外观与复杂度上限取决于前端,不锁死在任何 GUI 库**;载荷几乎不变。桌面快捷方式「WinVoice 设置」指向该模块。

## Phase 1 — 注释保留的配置写入(`winvoice/config_edit.py`,新模块,纯逻辑)

窗口是**首个运行时 config.yaml 写入者**,必须:①**原子写**(临时文件 + `os.replace`)——watchdog 0.5s 防抖读到半个 YAML 会让观察线程静默死亡(config.py:242-247);②**保注释**(yaml.safe_dump 整写会丢 400 行注释)。
- `update_keys(text, {点号路径: 值}) -> Optional[str]`:按行定位键就地改值;列表值(kws.keywords、tools.apps)整块替换;结构对不上返回 None → 调用方回退 yaml.safe_dump 全量写并在 UI 提示。
- `save_config(cfg, changes)`:读→改→原子替换。
- 单测:注释保留、列表块替换、原子性、`${VAR}` 行不受影响。

## Phase 2 — 白名单配置驱动化(assistant 侧消费)

1. config.yaml + config.template.yaml 的 `tools:` 下新增 `apps:`(每项 `id`/`说名`/`启动命令`/`映像名`(命令≠映像时必填,如微信 Weixin.exe)/`guest`(bool))与 `sensitive_apps:`(默认 `[cmd, powershell]`);两者加入 HOT_RELOADABLE;标注/清理死键 `tools.whitelist`(全仓无代码读取)。
2. `builtin.py`:三张静态表改为 `current_apps()`(内置 9 个 + config.apps 合并,每次调用读 get_config——内存 dict,便宜);配置项命令走直通分支(`_launch` 已支持 .exe/.cmd/控制台子系统);拒绝话术动态化。
3. `verifier.py:_expected_image` 改用 `current_apps()`(验证器只认 `.exe` 映像名,自动工作)。
4. `registry.py:validate_call`:OPEN_APP/CLOSE_APP 增加敏感门——`tier != full` 且 app ∈ sensitive_apps → 拒绝;**UNIMPLEMENTED.md:177「敏感应用名单」条目就此下线**。
5. 单测:自定义应用开/关/验证、guest 被拦、host 不受限、热改后下一次调用即见新表。

## Phase 3 — 应用发现(`winvoice/tools/appdiscovery.py`)

扫开始菜单(`%APPDATA%` + `%ProgramData%` 两处 Programs 的 .lnk,pywin32 COM 解析真目标)+ App Paths + 卸载注册表(DisplayName→InstallLocation),输出 `{label, path, image}` 候选,与现有白名单去重;枚举可注入以便测试。

## Phase 4 — 后端 API(`winvoice/webui/`)

- `__main__.py` → `server.py`:ThreadingHTTPServer 绑 `127.0.0.1:0`(临时端口);token 首启随机生成,连同实际端口写 `runtime/webui.json`;再启动时若旧端口仍存活则直接复用(单实例)。启动后自动开窗口(Edge --app 优先)。
- API 全部要求 token,仅本机:
  - `GET /api/v1/config` — 当前值
  - `POST /api/v1/config` — 变更集 → `config_edit.save_config` → 返回每键生效方式(即时/需重启)
  - `GET /api/v1/apps/scan` — 发现候选
  - `GET /api/v1/meta` — 版本、HOT_RELOADABLE/REQUIRES_RESTART 映射(UI 据此标注)
- 静态文件服务 `webui/static/`。

## Phase 5 — 前端(`winvoice/webui/static/`,vanilla JS,全中文)

单页四标签 + 顶栏保存按钮 + 每键生效徽标(✓即时 / ↻重启后):
1. **应用**:应用表(启用/说名/命令/映像/允许访客)+「扫描本机程序」勾选添加 + 手动添加/删除(仅自定义项)
2. **唤醒词**:列表编辑,校验 2-12 字、≤8 个(与向导同规则),标注重启生效
3. **语音**:音调滑块 0.5–2.0、语速、访客语速;标注重启生效(TtsEngine 启动读一次,tts.py:326-339)
4. **常规**:天气城市(热生效)+ 天气开关
手写 CSS 做出干净的深/浅色主题;无构建步骤;未来换框架只动 static/。

## 已知限制(如实记录)

- `import winvoice` 拉起 sherpa 全栈 → 服务启动 2-5s(窗口打开前);后续可做 `__init__` 懒加载优化,不在本分支。
- 改音调/语速/唤醒词需重启主进程;DSH/MCP 子进程的城市快照不热更——UI 如实标注。
- 试听(TTS 预览)需加载 Matcha 模型,本版不做。
- 分阶段可停:1-3 是能力底座(无 UI 也自成一体),4-5 才是界面,每步全绿再进下一步。
